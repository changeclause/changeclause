# First adoption

Inspect the target only within the user's authorized scope. Read existing AGENTS.md, CLAUDE.md, package scripts, compiler configuration, and test configuration before proposing edits.

1. Identify languages/frameworks and project boundaries. Current semantic analysis covers one isolated TypeScript/JavaScript project. Nested projects, Astro/Vue templates, dynamic dispatch, routing behavior and full API compatibility need explicit manual or other tool checks. Inventory/scope coverage alone is not semantic coverage.
2. Locate a built, version-pinned public ChangeClause checkout outside the target. Follow its `docs/quick-start.md` if setup is authorized. Use Node 24 and pnpm 10.29.3. Record its absolute location and commit, never a private development checkout or credentials in shared guidance. A developer-specific local path can remain in ignored local instructions; shared guidance can describe how to locate the checkout.
3. Choose a small real feature/fix. Reuse existing tests and compiler commands. Vitest execution import is supported; do not migrate a project's test runner just for adoption. For other runners, record their normal results as separate evidence and leave ChangeClause execution support unavailable.
4. Prefer `.changeclause/changes/<change-id>/spec.md` and `contract.yaml`. This is a file convention, not a configuration API. Reuse an existing convention if present. Include these and any agent-guidance additions in the agreed allowed paths when part of the evaluated diff. Keep generated evidence outside the target repository.
5. Adapt `../assets/project-instructions.md` as a small section in the existing AGENTS.md. Preserve unrelated instructions. When Claude guidance exists, add the same shared reference there; a CLAUDE.md `@AGENTS.md` import can share the instructions. Do not replace existing files or duplicate a large procedure.
6. Install the skill only in the selected agent's discovery location, following `docs/agent-integration.md` in the release checkout. Keep its references/assets together. Record the installed release. Explain that an agent skill is guidance; it neither enforces policy nor installs CI.

Return a short readiness note: supported checks, gaps, tool version, normal commands, chosen spec paths, and the next requested stage. Start advisory. Before promoting checks to a merge requirement, exercise meaningful failures and resolve mandatory unsupported criteria using an explicit review process.
